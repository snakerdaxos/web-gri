restaurantes/{slug}: nombre, descripcion, tipoCocina, direccion, activo, califProm: double, califCount: int
categorias/{autoId}: restauranteId, nombre, orden: int, activo

mesas/{codigoQR}: restauranteId, numero, capacidad, estado, updatedAt
reservas/{mesaId}_{yyyyMMdd}_{HH}: restauranteId, mesaId, mesaNumero, usuarioId, fecha: Timestamp(slot), fechaStr "yyyy-MM-dd", hora: int, numPersonas, estado "confirmada|cancelada", createdAt

Patrón de la tx de reserva (port de backend/app/services/reserva_service.py — ver archivo):
1. Lectura de mesas candidatas FUERA de la tx (query no bloquea): mesas where restauranteId==rid, capacidad >= personas, orderBy numero.
2. DENTRO runTransaction: por cada mesa candidata tx.get(reservas/{mesaId}_{yyyyMMdd}_{HH}) — la primera que NO existe es la elegida.
3. validarTransicion('mesa', mesa.estado, 'reservada') — idempotente: si ya está 'reservada' se tolera (no lanza); si está 'ocupada'/'limpieza' lanza.
4. tx.set(reserva, {...estado confirmada, createdAt serverTimestamp}) + si mesa estaba 'disponible' tx.update(mesa, estado reservada).
5. Sin candidata libre → throw controlado con mensaje "No hay mesas disponibles en ese horario".
Pitfall 3: el doc ID usa la fecha del SLOT (dato del cliente), NUNCA serverTimestamp.

Índices ya definidos (10-01): reservas restauranteId+fecha, reservas usuarioId+fecha DESC, productos restauranteId+categoriaId, mesas restauranteId+numero.
Reglas que aplican (10-01): reservas create solo isCliente + fecha > request.time + numPersonas 1..20 + mesa pertenece al restaurante; update cancelada por dueño futuro o staff.

<threat_model>
- **Anti sobre-reserva:** la unicidad la da el doc ID determinista {mesaId}_{fecha}_{HH} + tx.get DENTRO de la transacción (dos contendientes leen el mismo doc → Firestore serializa). PROHIBIDO "query luego create con autoId" (Pitfall: la query no bloquea docs futuros).
- **Reglas re-validan:** la app valida por UX (estado mesa, capacidad), las rules validan por seguridad (futuro, 1..20 personas, mesa del restaurante) — el cliente nunca es fuente de verdad.
- **Timezone:** fechaStr/hora y el inicio del slot se computan en TZ local (Bogotá en dev/prod Colombia); las rules comparan fecha > request.time (UTC server) — bloquea fechas pasadas groseras (suficiente v1, documentado).
- **Cancelar no libera mesa ajena:** revertir mesa solo si estado == 'reservada' y con validarTransicion; si estaba ocupada se deja (paridad Phase 5).
</threat_model>
