<threat_model>
**Amenazas que este plan mitiga (referencia VALIDATION.md T-02-01):**

1. **Password hashing débil o nulo** → Mitigación: bcrypt directo con `bcrypt.gensalt()` (cost 12 por defecto), `bcrypt.checkpw` constante-tiempo. NO passlib (congelado desde 2020 — Pitfall 1 del research).
2. **Algorithm confusion en JWT** → Mitigación: `jwt.decode(token, secret, algorithms=["HS256"])` SIEMPRE con `algorithms=` explícito (Pitfall 4). Centralizado en `decode_token()`.
3. **`verify_exp` desactivado por accidente** → Mitigación: NO pasar `options={"verify_exp": False}`. PyJWT verifica `exp` por defecto.
4. **Cross-type token use (access como refresh o viceversa)** → Mitigación: todo token lleva claim `type` ("access"|"refresh"); `get_current_user` rechaza type != "access" con 401; `/auth/refresh` rechaza type != "refresh" con 401 (Pitfall 6).
5. **bcrypt 72-byte truncation** → Mitigación: `UserCreate.password: str = Field(min_length=8, max_length=64)` (Pitfall 5).
6. **password_hash泄漏 en respuesta** → Mitigación: `UserRead` Pydantic model explícito SIN campo `password_hash`. NUNCA usar el modelo ORM como `response_model` (Pitfall 7).
7. **Email enumeration en register** → Trade-off documentado: duplicate email devuelve 409 (revela existencia). Aceptado para v1; mitigación alternativa (respuesta genérica) difiere a hardening Phase 9.
8. **Bootstrap secret en código** → Mitigación: SUPER_ADMIN_PASSWORD vive solo en `.env` (gitignored); `.env.example` solo tiene placeholder.
9. **MissingGreenlet post-commit** → Mitigación: `expire_on_commit=False` ya fijado en Phase 1 (Pitfall 8). NO regresarlo a True. Tras `commit()`, usar `await session.refresh(user)` para poblar defaults servidor (`id`, `created_at`).
</threat_model>
