El doc ID del restaurante DEBE casar con `^[a-z0-9]+(-[a-z0-9]+)*$`.
Motivo: el doc ID de mesa se deriva del rid (`GRI-MESA-{rid}-{NNN}`) y el escáner del cliente valida
`^GRI-MESA-[a-z0-9-]+-\d{3}$` en `app_cliente/lib/features/sesion_qr/scan_screen.dart:41`.
Un rid con mayúsculas o acentos deja las mesas **permanentemente inescaneables**.

Generador de slug de referencia (Dart puro, sin paquetes — el dominio es español):
```dart
const _acentos = {'á':'a','à':'a','ä':'a','â':'a','ã':'a','å':'a','é':'e','è':'e','ë':'e','ê':'e',
  'í':'i','ì':'i','ï':'i','î':'i','ó':'o','ò':'o','ö':'o','ô':'o','õ':'o','ú':'u','ù':'u','ü':'u',
  'û':'u','ñ':'n','ç':'c'};
final _slugValido = RegExp(r'^[a-z0-9]+(-[a-z0-9]+)*$');

String generarSlug(String nombre) {
  var s = nombre.toLowerCase().trim();
  _acentos.forEach((k, v) => s = s.replaceAll(k, v));
  s = s.replaceAll(RegExp(r'[^a-z0-9]+'), '-')
       .replaceAll(RegExp(r'-+'), '-')
       .replaceAll(RegExp(r'^-|-$'), '');
  return s;
}
bool slugEsValido(String s) => s.isNotEmpty && s.length <= 40 && _slugValido.hasMatch(s);
```

Escritura del restaurante (cliente directo — las rules ya lo permiten a `isSuper()`):
```dart
await db.doc('restaurantes/$slug').set({
  'nombre': nombre, 'descripcion': descripcion, 'tipoCocina': tipoCocina, 'direccion': direccion,
  'activo': true, 'califProm': 0.0, 'califCount': 0,
  'createdAt': FieldValue.serverTimestamp(),
});
```

⚠️ Trampa a evitar: un `.set()` sobre un slug que YA existe se evalúa como **update**, y la regla del
super solo permite cambiar `activo` → el usuario vería un `permission-denied` incomprensible en vez
de "ese identificador ya está en uso". Por eso hay que comprobar la existencia ANTES (la lectura de
`restaurantes` es pública: el check es barato).

Precedente de UI a imitar para la confirmación destructiva: `mesa_form_dialog.dart:155-171`
(AlertDialog de confirmación antes de borrar una mesa).

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-05-01 | Tampering | slug del restaurante | mitigate | `slugEsValido` aplicado antes de escribir, más el test que compone `GRI-MESA-{slug}-001` y lo valida contra la regexp real del escáner. Un slug con acentos o mayúsculas nunca llega a Firestore |
| T-11-05-02 | Elevation of Privilege | `crearRestaurante` desde el panel | transfer | La autorización real es `allow create: if isSuper()` en `firestore.rules`, ya cubierta por los tests de 11-04. El gate de UI es solo UX |
| T-11-05-03 | Tampering | `.set()` sobre un slug existente | mitigate | Check de existencia previo: evita convertir un alta en un update silencioso y da un mensaje correcto |
| T-11-05-04 | Denial of Service | desactivación accidental de un restaurante en producción | mitigate | AlertDialog de confirmación solo en el sentido destructivo, con el radio de impacto explícito |
