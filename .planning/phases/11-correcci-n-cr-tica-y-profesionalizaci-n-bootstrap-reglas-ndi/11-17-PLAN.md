**Paquete (VERIFICADO en la API de pub.dev el 2026-08-19):** `google_sign_in` **7.2.0**, publisher
verificado `flutter.dev`, publicado 2025-09-17. Requiere Flutter >= 3.29 (el repo tiene 3.47) y Dart

⚠️ **La API cambió por completo en 7.x. No usar la de 6.x** (`GoogleSignIn()` + `signIn()` +
`authentication.accessToken` ya no existen). Forma actual:
```dart
final signIn = GoogleSignIn.instance;
await signIn.initialize(serverClientId: googleWebClientId);   // idempotente
await signIn.attemptLightweightAuthentication();              // reanudar sin interacción
if (signIn.supportsAuthenticate()) {
  final GoogleSignInAccount cuenta = await signIn.authenticate(); // LANZA si se cancela; no devuelve null
  final String? idToken = cuenta.authentication.idToken;
}
```
En 7.x `GoogleSignInAuthentication` expone **solo `idToken`** (los access tokens salen del
`authorizationClient`, que aquí no hace falta: Firebase solo necesita el idToken).
`authenticate()` **no está soportado en Web** (`supportsAuthenticate()` devuelve false).

**Ramas de plataforma decididas:**
- **Web** → `FirebaseAuth.instance.signInWithPopup(GoogleAuthProvider())`, soportado por
  `firebase_auth` 6.5.7. Evita el botón renderizado del plugin, que obligaría a rediseñar la pantalla
  (prohibido por la decisión de identidad visual). No necesita SHA-1 ni el client ID en código.
- **Android/iOS** → `google_sign_in` 7.x con `serverClientId: googleWebClientId`, luego
  `GoogleAuthProvider.credential(idToken: idToken)` → `signInWithCredential`.

**Regla de `usuarios/{uid}` — comprobada, NO hay que tocarla:**
```
allow create: if signedIn() && request.auth.uid == uid
              && request.resource.data.role == 'cliente'
              && request.resource.data.restauranteId == null;
```
Un usuario de Google cumple los tres requisitos igual que un auto-registro. Un usuario de Google **no
obtiene claims**: su rol efectivo es "cliente" por ausencia de claim, exactamente como hoy. El
precedente de escritura del espejo está en `auth_controller.dart:123-165` (`RegisterController.submit`).

**Colisión de cuentas:** si el correo ya existe con email/contraseña, Firebase lanza
`FirebaseAuthException(code: 'account-exists-with-different-credential')`. Hay que traducirlo.

**Efecto colateral útil:** las cuentas de Google llegan con `email_verified: true`, lo que encaja con
el endurecimiento del bootstrap del plan 11-07 (que exige correo verificado).

**Frontera honesta de la cobertura automatizada.** `firebase_auth_mocks` no modela
`signInWithCredential`, `signInWithPopup` ni el plugin de Google (que necesita canales de plataforma
inexistentes en `flutter test`). Lo que SÍ es testeable, y lo único que este plan promete: la lógica
de post-ingreso (creación del espejo, idempotencia, nombre desde displayName), la traducción de
errores y el estado del botón — a través de una costura inyectable. El handshake real con Google

Auth no implementa el flujo de Google). Prohibido inventar cobertura del handshake mockeando el plugin.
