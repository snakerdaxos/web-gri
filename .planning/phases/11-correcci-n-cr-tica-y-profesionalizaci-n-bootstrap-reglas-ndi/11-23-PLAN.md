<objective>
Dejar de mentirle al usuario cuando falla el escaneo de una mesa: distinguir las cinco causas reales y
dar a cada una su mensaje, empezando por el `permission-denied`, que hoy se presenta como si el código
QR estuviera mal.

Purpose: bug con coste real, encontrado con el usuario. Escaneó una mesa y la app dijo *"No pudimos
abrir la mesa. Verifica el código e intenta de nuevo."*; estuvo revisando el QR, que era correcto. La
causa real fue primero un `permission-denied` (su cuenta tenía rol `super_admin` y la regla de crear
sesión exige `isCliente()`) y después que la app apuntaba a emuladores apagados. Dos causas
completamente distintas, el mismo mensaje, y ninguna de las dos tenía que ver con el código.
Output: clasificador único de fallos de Firebase, los cinco mensajes, y limpieza de los `catch`
genéricos del mismo flujo.
</objective>

`app_cliente/lib/features/sesion_qr/sesion_provider.dart:196-217` (`SesionController.abrir`):
```dart
try {
  return await abrirSesion(db, uid: uid, codigoQR: codigoQr);
} on SesionException {
  rethrow;                                   // 'Código de mesa inválido' | 'Mesa ocupada'
} on TransicionInvalidaException {
  throw const SesionException('La mesa no está disponible en este momento');
} catch (_) {                                // <-- AQUÍ cae permission-denied Y el fallo de red
  throw const SesionException(
      'No pudimos abrir la mesa. Verifica el código e intenta de nuevo.');
}
```
Ese `catch (_)` se traga dos cosas que no tienen nada que ver entre sí ni con el código QR:
`FirebaseException(code: 'permission-denied')` y `FirebaseException(code: 'unavailable')`.
`scan_screen.dart:100-110` remata con un segundo genérico ("Error de conexión. Intenta de nuevo.")
para cualquier excepción que no sea `SesionException`.

**Por qué un `super_admin` recibe permission-denied al escanear:** la regla de `sesiones` exige
`isCliente()` para el `create` (`firestore.rules`, match `/sesiones/{sesionId}`), y `isCliente()` es
"sin claim `role`, o `role == 'cliente'`". Una cuenta de staff o de plataforma NO puede abrir mesa: es
correcto por diseño, pero el usuario merece que se lo digan.

**Las cinco causas a distinguir** (el usuario las enumeró):

| Causa | Cómo se detecta | Mensaje |
|---|---|---|
| Formato de código inválido | La regexp del escáner (`scan_screen.dart:41`) o la `SesionException` de dominio | "Ese código no parece el de una mesa GRI. Revisa que estés escaneando el QR de la mesa." |
| Mesa inexistente | El doc `mesas/{codigo}` no existe | "Esa mesa no existe. Puede que el QR sea de otro restaurante o que la mesa se haya eliminado." |
| Mesa no disponible | `TransicionInvalidaException` / mesa ocupada o en limpieza | El mensaje actual, que ya es correcto |
| **Permiso denegado** | `FirebaseException(code: 'permission-denied')` | "Tu cuenta no puede abrir mesas. Entra con una cuenta de cliente para pedir desde la mesa." |
| **Fallo de red o backend** | `FirebaseException` con `unavailable`, `deadline-exceeded`, `cancelled`, `internal`, o cualquier `SocketException`/`TimeoutException` | "No pudimos conectar con el servidor. Revisa tu conexión e inténtalo de nuevo." |

Regla de oro del plan: **un `permission-denied` JAMÁS puede producir un mensaje que hable del código,
del QR o de la mesa**. Es un problema de quién eres, no de qué escaneaste.

**Detalle que ahorra horas en desarrollo:** la app se compila con
`--dart-define=USE_EMULATORS=true` para apuntar a los emuladores
(`core/firebase_bootstrap.dart`). Si ese define está activo y llega un `unavailable`, casi siempre
significa que los emuladores no están corriendo. Añadir esa pista **solo** en ese caso
(`const bool.fromEnvironment('USE_EMULATORS')` es constante de compilación, así que el texto ni existe
en el binario de producción): "…¿están corriendo los emuladores?". Es exactamente el segundo tropiezo
del incidente real.

**Otros `catch` genéricos del mismo flujo, a revisar con el mismo criterio:**
- `pedidos_provider.dart` (crear pedido, solicitar la cuenta)
- `menu_mesa_screen.dart:397-403` → "Error de conexión. Intenta de nuevo."
- `pedido_estado_screen.dart:64-69` → idéntico
- `calificacion_sheet.dart:171-175` → "No pudimos enviar tu calificación. Intenta de nuevo."
Los tres últimos dicen "error de conexión" ante CUALQUIER excepción, incluido un `permission-denied`.
