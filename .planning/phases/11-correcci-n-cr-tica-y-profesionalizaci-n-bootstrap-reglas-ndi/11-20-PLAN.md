## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet → callables desplegadas | A partir del deploy, las funciones son invocables desde fuera del producto |
| operador → facturación | Blaze abre un coste variable |
| `functions/.env` → secretos de bootstrap | El secreto de inicialización vive en un archivo local no versionado |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-20-01 | Elevation of Privilege | ventana entre el deploy de functions y el bootstrap | mitigate | `BOOTSTRAP_EMAIL` y `BOOTSTRAP_SECRET` se configuran ANTES del deploy y la función falla cerrada sin ellos; además exige `email_verified`. No existe ventana en la que un desconocido pueda hacerse super_admin |
| T-11-20-02 | Information Disclosure | `BOOTSTRAP_SECRET` | mitigate | Vive solo en `functions/.env`, excluido por `.gitignore`; el runbook prohíbe escribirlo en documentación o en el chat |
| T-11-20-03 | Denial of Service | coste inesperado en Blaze | mitigate | Presupuesto de alerta como paso obligatorio del runbook; se explica al usuario el orden de magnitud esperado y que Blaze mantiene la cuota gratuita |
| T-11-20-04 | Spoofing | callables invocadas por bots | accept | App Check queda DIFERIDO y documentado como deuda de seguridad conocida; mitigación parcial vía `maxInstances` y la matriz de autorización del servidor |
| T-11-20-05 | Repudiation | fase cerrada sin ejecutar el smoke | mitigate | El resume-signal distingue "approved" de "sin blaze": declinar es una decisión registrada, no un silencio |
