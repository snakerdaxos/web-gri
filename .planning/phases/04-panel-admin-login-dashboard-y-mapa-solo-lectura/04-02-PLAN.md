<threat_model>
T-04-05 (Token storage en Web): flutter_secure_storage 11.0 usa WebCrypto + LocalStorage en Web.
NO es Keystore/Keychain como en móvil; el key es browser-generated y same-domain-bound.
Tratar como "obfuscado, no cifrado". Aceptable para panel staff-only en localhost dev y
en prod HTTPS (Phase 9 nginx+TLS). INACEPTABLE para kiosk público. Documentar inline en
auth_storage.dart. Mitigación Phase 9: panel SIEMPRE sobre HTTPS, tokens TTL cortos
(ACCESS_TTL_MIN=15 ya configurado).

T-04-06 (Refresh storm): si N requests fallan con 401 al mismo tiempo, N refreshes
paralelos invalidan el access_token del primero (race). Mitigación: AuthInterceptor
extiende QueuedInterceptor (serializa) + un Completer<String?> compartido que bloquea
los N-1 errores mientras el primero hace el refresh. Solo 1 POST /auth/refresh; los demás
reciben el nuevo token del Completer y retry.

T-04-07 (Token leak vía widget): hardcoded tokens en widgets = leak a DevTools. Mitigación:
TODO HTTP va por apiClientProvider (única instancia dio con el interceptor). Widgets nunca
tocan storage ni tokens directamente. login_controller es la única puerta de escritura.

T-04-08 (Auth bypass en redirect): si el GoRouter.redirect lee authState mal (ej. considera
loading == loggedIn), usuario sin sesión entra al dashboard. Mitigación: redirect revisa
`authState.value` (AsyncData<User?>?) — solo AsyncData con User no-null está "logueado";
isLoading y AsyncError se tratan como "no logueado" (manda a /login). refreshListenable
obliga a re-evaluar el redirect cuando authState cambia.

T-04-09 (Cross-tenant display para super-admin): un super_admin con restaurant_id=null no
tiene tenant; sin resolver "qué restaurante ver", /staff/stats responde 400 (Plan 04-01).
Mitigación UI: AuthState detecta role==super_admin → dispara fetch /admin/restaurantes,
muestra dropdown; default al primer restaurante activo (decisión del planner, §Open Q1).
Staff usa restaurant_id del /auth/me directo, sin dropdown.
</threat_model>
